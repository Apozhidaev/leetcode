# Объяснение решения

## Идея

Медиана — это элемент(ы) по середине объединённого отсортированного массива.

Представим, что массивы уже слиты. Тогда все элементы делятся на две половины:

- **левая** — меньшая половина (всё, что ≤ медианы);
- **правая** — большая половина (всё, что ≥ медианы).

Медиана как раз на стыке этих половин: самый большой элемент слева (и, если длина чётная, ещё самый маленький справа).

Значит, нам не нужен сам объединённый массив — нужно только правильно собрать **левую половину**. А она всегда состоит из какого-то префикса `nums1` плюс какого-то префикса `nums2` (оба массива уже отсортированы). Поэтому задачу можно свести к поиску разреза: сколько элементов взять слева из первого массива и сколько — из второго.

Пример: `nums1 = [1, 3]`, `nums2 = [2]` → объединение `[1, 2, 3]`.
Левая половина — `[1, 2]`, медиана — `2` (максимум слева). Эти `1` и `2` — просто префиксы исходных массивов, разрезанных в нужных местах.

Пусть общая длина `m + n`. Тогда слева должно оказаться:

```text
half = (m + n + 1) / 2
```

элементов (целочисленное деление). Тогда:

- при нечётной длине медиана — максимум слева;
- при чётной — среднее максимума слева и минимума справа.

## Разбиение

Берём `i` элементов из `nums1` и `j = half - i` элементов из `nums2`:

```text
nums1: [........ left1 ........ | ........ right1 ........]
                     i элементов

nums2: [........ left2 ........ | ........ right2 ........]
                     j элементов
```

Разбиение корректно, если вся левая часть ≤ всей правой:

```text
max(left1) <= min(right2)
max(left2) <= min(right1)
```

Если одно из условий нарушено — двигаем границу:

- `max(left1) > min(right2)` → в `nums1` взяли слишком много слева → уменьшаем `i`;
- иначе → слишком мало слева → увеличиваем `i`.

## Почему бинарный поиск

Ищем `i` только в меньшем массиве (`0 … m`, где `m ≤ n`). На каждом шаге отбрасываем половину диапазона → **O(log(min(m, n)))**.

Память: **O(1)**.

## Краевые случаи

Если слева/справа у массива ничего нет, вместо отсутствующего значения берём `-∞` / `+∞`, чтобы сравнения оставались корректными.
